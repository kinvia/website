# Division-Integrated Success Cases Carousels Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Optimize all 15 client screenshots into WebP assets and embed two dual-animated horizontal case-study carousels inside `TwoAxes.astro` (`#divisiones` / `#axes`) — one under Cloud & Software (3 cases: Sercore, Ramos Calabria, CAPSA/UCAM) and one under IoT & Smart Spaces (2 cases: Villa Gran Alacant, Villa Punta Prima) in both Spanish and English.

**Architecture:** A deterministic `sharp` script (`scripts/optimize-case-images.mjs`) converts the 15 source JPEGs from `/tmp/kinvia/clientes/` into `public/images/cases/*.webp` (`1280px` max width, quality `82`). `src/i18n/es.json` and `src/i18n/en.json` store the structured bilingual copy and 3 module screenshots per case under `axes.cloud.cases`, `axes.iot.cases`, and `axes.casesLabels`. `TwoAxes.astro` mounts two `<SuccessCasesCarousel client:visible />` React islands (one per `.axis-column`), where each carousel independently animates client transitions (Option B horizontal track with side peek) and per-card 3-screenshot transitions.

**Tech Stack:** Astro 5 (SSG), React 19 (`@astrojs/react`), TypeScript, `sharp`, Vitest + Testing Library + JSDOM.

**Spec:** `docs/superpowers/specs/2026-10-28-success-cases-carousel-design.md`

## Global Constraints

- All 15 images in `/tmp/kinvia/clientes/` must be converted to `.webp` in `public/images/cases/` with max width `1280px` and file size `< 250 KB` each:
  - `sercore-1.webp`, `sercore-2.webp`, `sercore-3.webp`
  - `rc-1.webp`, `rc-2.webp`, `rc-3.webp`
  - `capsa-1.webp`, `capsa-2.webp`, `capsa-3.webp`
  - `iot-gran-alacant-1.webp`, `iot-gran-alacant-2.webp`, `iot-gran-alacant-3.webp`
  - `iot-punta-prima-1.webp`, `iot-punta-prima-2.webp`, `iot-punta-prima-3.webp`
- Keep the existing 5 top-level landing sections and localized anchors (`#inicio`, `#divisiones`, `#servicios`, `#modelos`, `#contacto` / `#hero`, `#axes`, `#services`, `#model`, `#contact`) unchanged.
- `.axis-column` in `TwoAxes.astro` must set `min-width: 0; display: flex; flex-direction: column;` so horizontal carousel tracks never cause CSS Grid column blowout.
- Animations must automatically disable when `[data-reduce-motion="true"]` or `@media (prefers-reduced-motion: reduce)` is active.

## Review Focus

- Clicking the peeking (non-active) client card in a division carousel activates that client card and updates `data-active-case`.
- Switching between client cards preserves or cleanly resets each card's internal screenshot index (`0..2`) without throwing out-of-bounds errors when a division has 2 cases (`iot`) vs 3 cases (`cloud`).
- Prev/Next client buttons wrap around cleanly (`0 -> last` on prev, `last -> 0` on next) for both 3-case and 2-case carousels.
- Prev/Next screenshot controls and module tab buttons (`1`, `2`, `3`) inside a card update only that card's active screenshot (`data-active-image`) without triggering a client card change (`e.stopPropagation()`).
- Every `images[].src` referenced in `es.json` and `en.json` exists in `public/images/cases/` and is `< 250 KB`.

      'sercore',

    for (const c of allCases) {
      expect(c.images).toHaveLength(3);
      expect(c.challenge.length).toBeGreaterThan(20);
      expect(c.solution.length).toBeGreaterThan(20);
      expect(c.impact.length).toBeGreaterThan(15);

      for (const img of c.images) {
        expect(img.src).toMatch(/^\/images\/cases\/[a-z0-9-]+-[123]\.webp$/);
        const filePath = path.resolve(process.cwd(), 'public', img.src.replace(/^\//, ''));
        expect(fs.existsSync(filePath)).toBe(true);
        const stat = fs.statSync(filePath);
        expect(stat.size).toBeGreaterThan(5000);
        expect(stat.size).toBeLessThan(250 * 1024);
      }
    }
  });
